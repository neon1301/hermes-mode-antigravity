# 🧭 Протокол «Руль» (Plan Gate, Auto-Spec EARS-lite & Mechanical Lessons — v4.7.0)

Данный модульный регламент дополняет ядро [`fleet-protocol.md`](fleet-protocol.md) без увеличения его байтового бюджета.

## 1. Порядок гейтов перед первой записью кода

Для всех **Standard / Complex** задач с новым поведением (независимо от выбранного режима Совета специалистов, включая «оркестр сам» и `councilGate: "off"`):

```
Шаг 0 (модель) → Совет-гейт (Council Gate) → План (.hermes/plan.md) → Подтверждение ([Делай]) → Код
```

- **Исключения (без расширения определения мелочи):** Micro/Fast-Path (`--fast-path`, одиночное «исправь опечатку»), прямой вызов `@специалист`, `/hermes fix-warnings`. Составные запросы (например, *«исправь опечатку и отрефактори модуль»*) **всегда** требуют план.
- **Артефакты:**
  - `.hermes/plan.md` — пишет Lead (meta-путь, доступен ДО подтверждения).
  - `.hermes/plan-state.json` — **ЗАЩИЩЁН** (входит в 14 неизменяемых защищённых путей), пишет только хук: `{ taskHash, conversationId, planHash, status: "confirmed", confirmedAt, version, confirmedAskStepIdx, confirmedAskToolCallId, reqIds }`.
  - `.hermes/plan-ledger.jsonl` — **ЗАЩИЩЁН**, append-only журнал каждого freeze, ревизии и drift/lint-события.

## 2. Одноэкранное окно плана для вайбкодера (обязательная структура `.hermes/plan.md`)

План пишется простым языком (без непрошенного техножаргона; технически обязательное не спрашивается — делается по стандарту и кратко сообщается; секреты никогда не зашиваются в код даже по просьбе). Обязательны 4 секции:

```markdown
## ВОТ ЧТО Я ПОНЯЛ (твоими словами)
- **П1 (REQ-1):** КОГДА <условие> — СИСТЕМА ДОЛЖНА <поведение>. Проверка: <тест или артефакт>.

## ВОТ ЧТО Я ДОБАВЛЮ САМ — ты этого не говорил
- **Д1 (REQ-2):** КОГДА <условие> — СИСТЕМА ДОЛЖНА <поведение>. Проверка: <тест или артефакт>.
*(Если добавок нет — честная строка: «Ничего сверх твоей просьбы — делаю ровно то, что ты сказал.»)*

## ЧЕГО Я НЕ ДЕЛАЮ
- <конкретные границы скоупа, без воды>

## СПРОШУ ТОЛЬКО ОДНО-ДВА
- <0–2 продуктовых вопроса, не технических; либо «Вопросов нет — всё понятно.»>
```

- **Оценка стоимости:** указывается честно диапазоном («оценка»), без выдуманных токенов (Rule 13).
- **Синхронизация реестра:** пункты `REQ-1..N` плана синхронизируются с единственным реестром `.hermes/tasks.json` (`reqLedger`).
- **Опции окна подтверждения (`ask_question`):**
  1. `Делай` — подтверждение и заморозка плана v1 (`plan-state.json`).
  2. `Убрать лишнее` — путь ревизии v2 (НЕ согласие, запись заблокирована).
  3. `Добавить своё` — путь ревизии v2 (НЕ согласие, запись заблокирована).
- **Валидация согласия:** привязка строго к **тексту выбранной опции** (не к номеру), Cyrillic negation-guard («не надо план, делай сразу», «план не подтверждаю», «никакого плана» -> `deny`), Edit-Dominance («Делай, но убери Д1» -> `deny`), разговорные одобрения («Делай, без проблем» -> `allow`), строгий запрет `MODEL`-прозы и `<SYSTEM_MESSAGE>`-эхо.
- **Ревизия v2:** любая правка `.hermes/plan.md` после подтверждения вызывает SHA-256 mismatch (`plan_tampered`) и блокирует запись кода до нового подтверждения `v2` (старая версия сохраняется в `.hermes/plan-ledger.jsonl`).

## 3. EARS-lite Lint при заморозке плана

При заморозке хук `hooks/plan-gate.mjs` механически проверяет:
1. Наличие всех 4 секций и непустоту «Понял» и «Чего я не делаю» (в «Добавлю сам» допускается честная пустота).
2. Для каждого пункта «Понял» и «Добавлю сам» — непустые `КОГДА`, `ДОЛЖНА` и `Проверка:` (заглушки вроде `Проверка: ок` / `вручную` / `TBD` целиком отклоняются).
3. **Претензия «так принято» (`best practice`, `общепринято`, `по стандарту`):** обязана нести `https://` URL + дословную цитату + дату (inline или сноской `[n]` в секции `## Источники`), существующую локальную ссылку `path:line`, либо честную пометку `«мой выбор, не конвенция»`. *Машина не проверяет смысл плана и цитат — см. `docs/known-boundaries.md`.*

## 4. Отчёт по задаче (Rule 13)

Финальный отчёт включает таблицу **«Пункт → Проверка → Факт»** и обязательную строку **«Чего НЕ сделал»**:

| Пункт плана | Проверка | Факт |
| :--- | :--- | :--- |
| REQ-1 | `npm test` (`...`) | ✅ PASS (`...`) |

**Чего НЕ сделал:** явный перечень исключённого из скоупа или невыполненного. «Готово» без проверяемых фактов не принимается.

## 5. TDD Red-фаза (`pre-implementation`) и Механические уроки (`.hermes/lessons.jsonl`)

- **TDD `pre-implementation`:** провалы `test-summary.json` до первой записи production-исходника (когда в текущем `taskHash` правились только тест-файлы по `isStrictTestPath`) записываются в `.hermes/progress-journal.jsonl` с `phase: "pre-implementation"` и не увеличивают `consecutiveFails`. Первая запись не-тестового исходника необратимо переводит задачу в `phase: "implementation"` (однонаправленная защёлка; `qa-verdict`/`security-verdict` всегда `implementation`).
- **`.hermes/lessons.jsonl` (ЗАЩИЩЁН, append-only):** пишется только хуками (`hooks/clean-edits-guard.mjs`, `hooks/qa-gate.mjs`) из реальных событий: `QA REJECT` на Stop, повторный `deny` (`>= 2` по одному `rule` в задаче), срабатывание предохранителя (`stall_breaker`). Запись: `{ ts, taskHash, rule, reasonHash, count, source: "mechanical" }`. `hooks/context-injector.mjs` подгружает последние `<= 5` уникальных механических записей в бюджете `<= 2048` UTF-8 байт со статическими подсказками (`RULE_HINTS`). Lead может вести человекочитаемый `.hermes/lessons.md`, но источником истины остаётся защищённый `lessons.jsonl`.

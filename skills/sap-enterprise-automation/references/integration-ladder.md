# 🪜 7-Ступенчатая лестница интеграции с SAP (Enterprise Integration Ladder)

Методология выбора архитектурного уровня взаимодействия с экосистемой SAP (ERP, S/4HANA, ECC) силами специалиста `@ruslan`.

---

## 🏛️ Принцип «Экспорт — спроектированный путь» (Export is a Designed Path)
В корпоративных ERP-системах класса SAP любая прямая неконтролируемая запись в таблицы БД нарушает транзакционную целостность и условия поддержки SAP. Лестница интеграции определяет строгий порядок выбора инструментария — от нативных сертифицированных интерфейсов к пакетным выгрузкам. Пакетный регламентный экспорт является спроектированным и легитимным маршрутом интеграции.

---

## 🪜 7 Ступеней лестницы корпоративной интеграции

### Ступень 1: Vendor MCP (Официальный SAP MCP Сервер)
- **Приоритет:** Наивысший (Tier 1).
- **Суть:** Официальный SAP AI Core / BTP MCP сервер с поддержкой сертифицированных корпоративных политик безопасности.

### Ступень 2: Community MCP (Проверенный SAP MCP Коннектор)
- **Приоритет:** Высокий (Tier 2).
- **Суть:** Проверенные коннекторы сообщества для SAP OData сервисов и каталогов метаданных.

### Ступень 3: Typed OData / BAPI Wrapper (NCo 3.0/3.1.x & OData v2/v4)
- **Приоритет:** Высокий (Tier 3).
- **Суть:** Типизированные клиенты на C#/.NET на базе SAP .NET Connector (NCo) для BAPI/RFC транзакций (`BAPI_TRANSACTION_COMMIT` / `ROLLBACK`) или REST/OData API шлюза SAP Gateway.
- **Обязательно:** Строгое соблюдение BAPI Return structure (`BAPIRET2`) и обработка CSRF токенов.

### Ступень 4: Read-Only Database View / CDS Views (SAP HANA / S/4HANA)
- **Приоритет:** Средний (Tier 4).
- **Суть:** Использование SAP Core Data Services (CDS Views) с аннотациями `@Analytics.query: true` или Read-Only представлений для выборки сводных аналитических данных без транзакционной нагрузки на транзакционное ядро.

### Ступень 5: Bridge Service (Асинхронные IDoc/ALE Очереди)
- **Приоритет:** Умеренный (Tier 5).
- **Суть:** Асинхронный обмен через транзакционные очереди IDoc (Intermediate Document) с поддержкой tRFC/qRFC, гарантирующие семантику Exactly-Once Delivery и изоляцию корпоративных контуров.

### Ступень 6: Screen Automation (SAP GUI Scripting)
- **Приоритет:** Резервный (Tier 6).
- **Суть:** Автоматизация через `SapROTWr.dll` / SAP GUI Scripting Engine для устаревших транзакций, где отсутствуют BAPI и OData.
- **Обязательно:** Строгая изоляция COM-объектов через `Marshal.ReleaseComObject` в блоках `finally` для предотвращения утечек памяти дескрипторов процесса `saplogon.exe`.

### Ступень 7: Scheduled CSV/JSON Export (Регулярная пакетная выгрузка ALV)
- **Приоритет:** Фундаментальный спроектированный путь (Tier 7).
- **Суть:** Регулярная регламентная выгрузка отчётов (ALV Grid, транзакции SE16N/FBL3N/SQVI) в фоновых пакетных заданиях (SAP Background Jobs `SM37`) в защищённые каталоги обмена.
- **Плюсы:** Нулевой риск блокировки блокировочных таблиц (`SM12`), 100% изоляция продуктивного сервера SAP от внешних сбоев.

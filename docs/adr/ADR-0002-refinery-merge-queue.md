# ADR 0002: Легковесная очередь слияния Refinery (Gas Town Merge Queue Architecture)

## Статус
Принято (Accepted) — Релиз v4.0.0 (Фаза 0: Архитектурный дизайн)

## Контекст
В рамках методологии Gas Town (`gastownhall/gastown`), описанной в `skills/hermes/references/orchestrator-parallel.md`, параллельные пишущие воркеры (Контур B) вносят изменения в изолированных ветках воркспейса (`Workspace: "branch"` или `"share"`).
Ранее слияние параллельных веток осуществлялось Оркестратором вручную через серию команд `git merge`. При возникновении регрессий в одной из веток ручной поиск виновной ветки требовал многократных прогонов Single Build Gate, отнимал контекстное окно и затягивал цикл сходимости.

Перед командой стояла задача автоматизировать процесс слияния и бисекции (TASK-003):
- Без установки стороннего Go-бинарника `gt` (Gas Town CLI).
- Без нарушения инвариантов fail-open и zero-context вне Hermes.
- Без нарушения правила Anti-Premature Kill.
- Без использования временных patch-скриптов (.ps1, .bat, .py) — Rule 8.
- С сохранением чистоты Single Build Gate.

## Анализ точек перехвата (Interception Points)

### 1. Вариант A: PreToolUse хук на `run_command git` (ОТКЛОНЁН)
* **Проблема:** Хуки платформы Antigravity имеют жёсткий таймаут выполнения (10 секунд). Прогон сборочного гейта (`npm test`, `dotnet test`, `verify.ps1`) занимает от 5 до 15 секунд, а бисекция нескольких веток может потребовать 30–60 секунд.
* **Риск:** Превышение таймаута хука приведёт к блокировке или сбою платформенного пайплайна, нарушая фундаментальный принцип fail-open.
* **Вердикт:** Архитектурно неприемлемо.

### 2. Вариант B: Stop хук (ОТКЛОНЁН)
* **Проблема:** Хук `Stop` предназначен для валидации артефактов текущего хода (`security-verdict.json`, clean edits, gate-log). Исполнение долгоживущих git-операций перебазирования и прогона тестов в Stop-хуке перегружает его ответственность и подвержено тем же рискам 10-секундного таймаута.
* **Вердикт:** Архитектурно неприемлемо.

### 3. Вариант C: Локальная специализированная утилита `scripts/refinery.mjs` (ПРИНЯТ)
* **Преимущества:**
  - Запускается Оркестратором как стандартный инструмент в пространстве пользователя (`node scripts/refinery.mjs`).
  - Не ограничена 10-секундным платформенным таймаутом хуков.
  - Имеет прямой доступ к stdout/stderr компиляторов и тестовых раннеров.
  - Легко тестируется автономными модульными и интеграционными тестами (`hooks/refinery.test.mjs`).
  - Полностью соответствует Rule 8 (является постоянным версионируемым модулем кодовой базы, а не временным hotfix-патчем).
* **Вердикт:** Принят к реализации.

## Архитектурное Решение

### 1. Компонент `scripts/refinery.mjs`
Реализуется модуль на чистом Node.js (ESM), предоставляющий как CLI-интерфейс, так и программный API для:
1. Валидации имён веток (защита от shell injection через regex `^[a-zA-Z0-9_\-\./]+$`, запрет флагов `--*`).
2. Создания временной интеграционной ветки (по умолчанию `hermes/refinery-staging-<timestamp>`).
3. Серийного слияния кандидатов в staging-ветку (`git merge --no-ff --no-commit`).
4. Запуска верификационного гейта (Single Build Gate: configurable command, по умолчанию `npm test` или `npm run verify`).
5. **Бисекции при сбое (Bisect on Red):**
   - Если объединённый батч не проходит проверку, запускается бисекция:
     - Одиночная проверка или половинное деление кандидатов.
     - Точная изоляция ветки, внесшей регрессию.
     - Маркировка виновной ветки статусом `REJECTED` с записью точного лога ошибки.
     - Интеграция оставшихся зелёных веток в целевую ветку (`main`).
6. **Гарантия атомарного отката (Fail-Open & Rollback Guarantee):**
   - При любых непредвиденных ошибках (конфликт слияния, прерывание процесса) утилита гарантирует вызов `git merge --abort` и возврат на исходную ветку без грязных файлов в рабочем дереве.

### 2. Интеграция с графом задач Beads (`.hermes/tasks.json`)
Refinery синхронизирует статусы задач воркеров:
- Ветка принята и тесты зелены: статус задачи обновляется на `DONE`.
- Ветка сломала сборку (отсеяна бисекцией): статус обновляется на `FAILED` с полем `mergeError`, задача возвращается в бэклог для исправления воркером.
- Инвариант Anti-Premature Kill: утилита `refinery.mjs` **никогда** не вызывает `manage_subagents kill`. Очистка субагентов остаётся исключительной прерогативой Оркестратора после полного завершения интеграции.

### 3. Границы автоматизации (Что НЕ автоматизируется)
1. **Push в удалённый репозиторий:** `git push origin` никогда не выполняется автоматически Refinery; публикация происходит строго по явной команде пользователя.
2. **Разрешение 3-way конфликтов:** При конфликте слияния Refinery не пытается эвристически слить код. Конфликтующая ветка отклоняется с указанием конфликтующих файлов.
3. **Установка внешних бинарников:** Никаких сторонних бинарников (включая Go-бинарник `gt`) не устанавливается. Используется стандартный рантайм Node.js и системный `git`.

# Hermes Fleet Troubleshooting Guide

## 1. Mechanical QA Gate Rejection (`qa-verdict.json rejected`)

### Symptom
On Stop, Hermes Gate blocks termination with message:
```text
Hermes Gate: [QA PASS] (Viktor) missing
```
or `.hermes/gate-log.jsonl` contains:
```json
{"decision":"continue","reason":"qa-verdict.json rejected: mechanical verification check failed"}
```

### Cause
In Hermes Fleet v4.1.0+, `qaVerdictMode` defaults to `"artifact"`. A text token `[QA PASS]` in the transcript is no longer sufficient. A valid `.hermes/qa-verdict.json` generated by `hooks/qa-runner.mjs` is required.

### Resolution
1. **Run Mechanical QA Runner:**
   ```bash
   node hooks/qa-runner.mjs
   ```
   This automatically detects your stack (`dotnet`, `pytest`, `npm`, `go`), executes the test suite, captures process exit codes, and writes `.hermes/qa-verdict.json`.
2. **Check Invariant Requirements:**
   - `runner` must be `"mechanical"`.
   - All `testExitCodes` must be `0`.
   - `diffHash` must match the working tree state (re-run `qa-runner.mjs` after any code edit).
   - Artifact must be fresh (TTL <= 5 minutes).
3. **Temporary Legacy Compatibility:**
   If you need to bypass mechanical artifact requirement temporarily, set in `.hermes/config.json`:
   ```json
   {
     "qaVerdictMode": "legacy"
   }
   ```
   Or set environment variable:
   ```bash
   export HERMES_QA_VERDICT_MODE=legacy
   ```
   *(Note: `legacy` mode is deprecated and will be removed in v5.0.0; see ADR-0005).*

## 3. Testing External Projects in Antigravity (`payload.workspacePaths`)

### Symptom
When running Hermes on an external project, `qa-gate` reports diffHash mismatches, empty `reqLedger` (`reqLedger is empty`), or fails to find `.hermes/tasks.json`.

### Root Cause
Antigravity provides `payload.workspacePaths` pointing to the workspace folder currently opened in the IDE window (`File -> Open Folder`). If an external project is edited while the Antigravity window has the plugin repo (or another repo) opened, `qa-gate` and `clean-edits-guard` evaluate the window's root workspace, not the child/external folder.

### Resolution
1. **Open Dedicated Window:** Open the external project via `File -> Open Folder` in a separate Antigravity IDE window so `payload.workspacePaths` points directly to the project root.
2. **Bootstrap Requirements Ledger:**
   In the project root, create `.hermes/tasks.json` with all task requirements:
   ```json
   {
     "tasks": [
       { "id": "REQ-1", "title": "Core functionality", "status": "DONE" }
     ]
   }
   ```
   Or pass requirements explicitly via CLI:
   ```bash
   node <plugin-path>/hooks/qa-runner.mjs --reqLedger=REQ-1,REQ-2 --viktorUuid=<uuid> --conversationId=<convId> --turnMarker=<turn>
   ```
3. **Ad-Hoc Opt-Out:**
   For quick scratch projects without requirement tracking, disable strict requirement ledger enforcement:
   ```bash
   node <plugin-path>/hooks/qa-runner.mjs --requireReqLedger=false
   ```
   Or configure in `.hermes/config.json`:
   ```json
   {
     "requireReqLedger": false
   }
   ```
   *(Note: This flags `reducedAssurance: "empty-ledger-opt-out"` in the generated verdict).*

## 3. Council Gate Rejection (Pre-Plan Specialist Consultation)

### Symptom
On write or worker launch, `clean-edits-guard` blocks the tool call with message:
```text
Hermes Gate (Council Gate): Первая запись задачи (<tool>) заблокирована! До перехода к правкам кода или созданию воркеров Lead обязан провести Council Gate — определить затронутые домены по specialist-dispatch-matrix.md и вызвать ask_question: «Посоветоваться с советом специалистов до финального плана?»
[EN: Hermes Gate (Council Gate): First write of task (<tool>) is blocked until Council Gate is completed via ask_question.]
```

### Cause
In active `/hermes` orchestrations for Standard/Complex tasks, Lead must not cut corners solo in Phase 2. Writing source code or spawning write subagents without a verified Council Gate decision is blocked.

### Resolution
1. **Interactive Flow (ask_question):** Call `ask_question` with 3 options:
   - `(Recommended) Собрать совет: <специалисты> — параллельные мнения + сравнительная таблица`
   - `Только ключевой специалист: <специалист>`
   - `Нет, Lead решает сам (экономия токенов)`
2. If **«Lead сам»** is selected by the user, writes are unlocked immediately.
3. If **«Собрать совет»** is chosen, summon the recommended specialists in Contour A (read-only), wait for their deliveries, present the comparative table and synthesis, and write `.hermes/decisions.md` and `.hermes/council-state.json`.
4. **Exceptions & Configuration:**
   - Trivial Micro/Fast-Path edits and `/hermes fix-warnings` bypass the gate automatically.
   - Configure in `.hermes/config.json`: `"councilGate": "off"` (bypass) or `"councilGate": "auto"` (auto-convene without dialog, deliveries still mandatory).

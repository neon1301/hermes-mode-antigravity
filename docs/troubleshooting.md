# Hermes Fleet Troubleshooting Guide

## 1. Mechanical QA Gate Rejection (`qa-verdict.json rejected`)

### Symptom
On Stop, Hermes Gate blocks termination with message:
```text
Hermes Gate: [QA PASS] (Viktor) missing
```
or `.hermes/gate-log.jsonl` contains:
```json
{"decision":"continue","reason":"qa-verdict.json rejected: mechanical verification check failed"}
```

### Cause
In Hermes Fleet v4.1.0+, `qaVerdictMode` defaults to `"artifact"`. A text token `[QA PASS]` in the transcript is no longer sufficient. A valid `.hermes/qa-verdict.json` generated by `hooks/qa-runner.mjs` is required.

### Resolution
1. **Run Mechanical QA Runner:**
   ```bash
   node hooks/qa-runner.mjs
   ```
   This automatically detects your stack (`dotnet`, `pytest`, `npm`, `go`), executes the test suite, captures process exit codes, and writes `.hermes/qa-verdict.json`.
2. **Check Invariant Requirements:**
   - `runner` must be `"mechanical"`.
   - All `testExitCodes` must be `0`.
   - `diffHash` must match the working tree state (re-run `qa-runner.mjs` after any code edit).
   - Artifact must be fresh (TTL <= 5 minutes).
3. **Temporary Legacy Compatibility:**
   If you need to bypass mechanical artifact requirement temporarily, set in `.hermes/config.json`:
   ```json
   {
     "qaVerdictMode": "legacy"
   }
   ```
   Or set environment variable:
   ```bash
   export HERMES_QA_VERDICT_MODE=legacy
   ```
   *(Note: `legacy` mode is deprecated and will be removed in v5.0.0; see ADR-0005).*

## 2. Mutation Testing Advisory vs Strict Mode

### Symptom
Gate blocks with mutation rejection or warning in logs.

### Explanation
- Default mode is `"advisory"`. Mutation testing runs under a budget of <= 20 mutants and 60s timeout, but does not block the gate if mutants survive.
- If `mutationMode` is explicitly configured as `"strict"` in `.hermes/config.json` or `HERMES_MUTATION_MODE=strict`, any survived mutant will reject the gate until killed by additional tests.
- When no mutation tooling (Stryker, mutmut) is installed, `qa-runner.mjs` reports `mutation: "unavailable"` adhering to Rule 13 (Data Honesty), which never blocks the gate.

# Hermes Fleet Troubleshooting Guide

## 1. Mechanical QA Gate Rejection (`qa-verdict.json rejected`)

### Symptom
On Stop, Hermes Gate blocks termination with message:
```text
Hermes Gate: [QA PASS] (Viktor) missing
```
or `.hermes/gate-log.jsonl` contains:
```json
{"decision":"continue","reason":"qa-verdict.json rejected: mechanical verification check failed"}
```

### Cause
In Hermes Fleet v4.1.0+, `qaVerdictMode` defaults to `"artifact"`. A text token `[QA PASS]` in the transcript is no longer sufficient. A valid `.hermes/qa-verdict.json` generated by `hooks/qa-runner.mjs` is required.

### Resolution
1. **Run Mechanical QA Runner:**
   ```bash
   node hooks/qa-runner.mjs
   ```
   This automatically detects your stack (`dotnet`, `pytest`, `npm`, `go`), executes the test suite, captures process exit codes, and writes `.hermes/qa-verdict.json`.
2. **Check Invariant Requirements:**
   - `runner` must be `"mechanical"`.
   - All `testExitCodes` must be `0`.
   - `diffHash` must match the working tree state (re-run `qa-runner.mjs` after any code edit).
   - Artifact must be fresh (TTL <= 5 minutes).
3. **Temporary Legacy Compatibility:**
   If you need to bypass mechanical artifact requirement temporarily, set in `.hermes/config.json`:
   ```json
   {
     "qaVerdictMode": "legacy"
   }
   ```
   Or set environment variable:
   ```bash
   export HERMES_QA_VERDICT_MODE=legacy
   ```
   *(Note: `legacy` mode is deprecated and will be removed in v5.0.0; see ADR-0005).*

## 2. Testing External Projects in Antigravity (`payload.workspacePaths`)

### Symptom
When running Hermes on an external project, `qa-gate` reports diffHash mismatches, empty `reqLedger` (`reqLedger is empty`), or fails to find `.hermes/tasks.json`.

### Root Cause
Antigravity provides `payload.workspacePaths` pointing to the workspace folder currently opened in the IDE window (`File -> Open Folder`). If an external project is edited while the Antigravity window has the plugin repo (or another repo) opened, `qa-gate` and `clean-edits-guard` evaluate the window's root workspace, not the child/external folder.

### Resolution
1. **Open Dedicated Window:** Open the external project via `File -> Open Folder` in a separate Antigravity IDE window so `payload.workspacePaths` points directly to the project root.
2. **Bootstrap Requirements Ledger:**
   In the project root, create `.hermes/tasks.json` with all task requirements:
   ```json
   {
     "tasks": [
       { "id": "REQ-1", "title": "Core functionality", "status": "DONE" }
     ]
   }
   ```
   Or pass requirements explicitly via CLI:
   ```bash
   node <plugin-path>/hooks/qa-runner.mjs --reqLedger=REQ-1,REQ-2 --viktorUuid=<uuid> --conversationId=<convId> --turnMarker=<turn>
   ```
3. **Ad-Hoc Opt-Out:**
   For quick scratch projects without requirement tracking, disable strict requirement ledger enforcement:
   ```bash
   node <plugin-path>/hooks/qa-runner.mjs --requireReqLedger=false
   ```
   Or configure in `.hermes/config.json`:
   ```json
   {
     "requireReqLedger": false
   }
   ```
   *(Note: This flags `reducedAssurance: "empty-ledger-opt-out"` in the generated verdict).*

## 3. Council Gate Rejection (Pre-Plan Specialist Consultation)

### Symptom
On write or worker launch, `clean-edits-guard` blocks the tool call with message:
```text
Hermes Gate (Council Gate): Первая запись задачи (<tool>) заблокирована! До перехода к правкам кода или созданию воркеров Lead обязан провести Council Gate — определить затронутые домены по specialist-dispatch-matrix.md и вызвать ask_question: «Посоветоваться с советом специалистов до финального плана?»
[EN: Hermes Gate (Council Gate): First write of task (<tool>) is blocked until Council Gate is completed via ask_question.]
```

### Cause
In active `/hermes` orchestrations for Standard/Complex tasks, Lead must not cut corners solo in Phase 2. Writing source code or spawning write subagents without a verified Council Gate decision is blocked.

### Resolution
1. **Interactive Flow (ask_question):** Call `ask_question` with 3 canonical options:
   - `(Recommended) Посоветоваться с работниками: @имена — независимые мнения + синтез (1 раунд)`
   - `🗣️ Собраться за столом: @имена — живое обсуждение, 3 стадии (NGT/Дельфи)`
   - `Нет, оркестр решает сам (экономия токенов)`
2. If **«Нет, оркестр решает сам»** is selected by the user, writes are unlocked immediately.
3. If **«Посоветоваться с работниками»** or **«Собраться за столом»** is chosen, summon the recommended specialists in Contour A (read-only), wait for their authentic deliveries, present the comparative table and synthesis, and write `.hermes/decisions.md` (`.hermes/council-state.json` is written exclusively by the hook).
4. **Exceptions & Configuration:**
   - Trivial Micro/Fast-Path edits, direct `@specialist` calls, and `/hermes fix-warnings` bypass the gate automatically (every bypass logs its explicit `source` in `.hermes/gate-log.jsonl`).
   - A **human user** (outside agent tools) may configure `.hermes/config.json` with `"councilGate": "off"` (bypass) or `"councilGate": "auto"` (auto-convene without dialog, deliveries still mandatory). Agents are strictly blocked from creating or editing `.hermes/config.json` via `write_file`/`edit_file`/shell commands; missing or invalid config fails closed to `"ask"`.

## 4. Plan Gate Rejection («Руль» — v4.7.0)

### Symptom
Before writing source code or spawning write workers (`define_subagent`, `swarm`, `invoke_subagent(self)`), `clean-edits-guard` blocks with a 3-line message containing one of the codes:
- `plan_missing` — `.hermes/plan.md` does not exist.
- `plan_unconfirmed` — `.hermes/plan.md` exists, but authentic `[Делай]` confirmation is missing (MODEL prose and `<SYSTEM_MESSAGE>` echoes are rejected).
- `plan_revision_pending` — user selected `[Убрать лишнее]` / `[Добавить своё]` or edit phrasing («Делай, но убери Д1»).
- `plan_negated_consent` — user negated the plan («не надо план, делай сразу», «план не подтверждаю», «никакого плана»).
- `plan_lint_failed` — `.hermes/plan.md` failed EARS-lite lint (missing 4 required sections, missing/stub `КОГДА`/`ДОЛЖНА`/`Проверка:`, or bare «так принято» without source/honest marker).
- `plan_tampered` / `plan_stale` — `.hermes/plan.md` was modified after confirmation (`v1 -> v2`) or after `ask_question` was sent.

### Cause
For Standard/Complex tasks with new behavior, Plan Gate operates independently of Council Gate mode (including solo or `councilGate: "off"`). `.hermes/plan-state.json`, `.hermes/plan-ledger.jsonl`, and `.hermes/lessons.jsonl` are protected artifacts (14 total) written exclusively by hooks.

### Resolution
1. Write or update `.hermes/plan.md` (meta-path, writable before confirmation) with the 4 required sections (`ВОТ ЧТО Я ПОНЯЛ`, `ВОТ ЧТО Я ДОБАВЛЮ САМ`, `ЧЕГО Я НЕ ДЕЛАЮ`, `СПРОШУ ТОЛЬКО ОДНО-ДВА`) and EARS-lite items (`КОГДА ... — СИСТЕМА ДОЛЖНА ... Проверка: ...`).
2. For any «так принято» / `best practice` claim, include `https://` URL + verbatim quote + date (inline or `## Источники` `[n]`), an existing local `path:line`, or the honest marker «мой выбор, не конвенция».
3. Present the 1-screen plan and invoke `ask_question` with `[Делай]`, `[Убрать лишнее]`, `[Добавить своё]`. Revisions (`v2`) require fresh confirmation.
4. Trivial Micro/Fast-Path edits (`--fast-path`, standalone typo fix), direct `@specialist`, and `/hermes fix-warnings` bypass automatically; a human user may disable Plan Gate via `"planGate": "off"` in `.hermes/config.json` or `HERMES_PLAN_GATE=off`.

## 5. Independent Grader, Team-Stop & L2 Binding («Инспектор» — v4.7.1)

### Symptom
- **Stop (`qa-gate.mjs`) blocks** with `grade_missing`, `grade_conflict_of_interest`, `grade_hash_mismatch`, `grade_incomplete_coverage`, `grade_evidence_invalid`, `grade_overall_mismatch`, `grade_rework_required`, `grade_rework_ceiling`, `grade_needs_human`, `grade_override_negated`, or `l2_binding_uncertain`.
- **PreToolUse (`clean-edits-guard.mjs`) blocks** Lead and subagent writes/write-spawns with `team_stop_active`, blocks plan `ask_question` dialogs containing internal ID walls (`plan_ask_mirror_invalid`), rejects `--fast-path` on complex tasks (`fast_path_complex_rejected`), and blocks direct agent writes into `logs/` (`logs_direct_write_deny`).

### Cause
1. **Independent Grader (`grade_*`):** Tasks with a confirmed plan derive protected `.hermes/rubric.json` and require an authentic `hermes-grade` `PASS` from a read-only specialist outside `councilRoster ∪ writeWorkers ∪ {Lead}` (`qaVerdictMode="legacy"`, `economy skip`, and `MAX_RETURNS = 2` do not bypass it).
2. **Team-Stop (`team_stop_active`):** Triggered by hard violations (`sec_l1_pattern`, `tamper_protected` file-write/shell, or `plan_tampered`), writing protected `.hermes/team-stop.json` (`status: "active"`). Protected paths list expanded to **19** built-in paths.
3. **L2 Binding (`l2_binding_uncertain`):** Multiple L2 auditor/grader invocations in a single step without `tool_call_id` are rejected fail-closed (`TASK-005`).
4. **Plan Mirror & Fast-Path & Black Box (`plan_ask_mirror_invalid`, `--fast-path`, `logs_direct_write_deny`):** Plan `ask_question` windows must show a plain-language 4-section mirror without internal codes (`REQ-*`/`FINDING-*`/`HIGH-*`); `--fast-path` is strictly for trivial edits (for human gate overrides use `.hermes/config.json` or env); `logs/` is populated solely by `node scripts/export-logs.mjs`.

### Resolution
1. For **`grade_*`**: invoke a free read-only specialist with `.hermes/rubric.json`, `.hermes/*`, and `git diff` (see `skills/hermes/references/independent-grading-protocol.md`). On `NEEDS_HUMAN` or 3/3 `REWORK` ceiling, request a validated user choice via `ask_question` («Принять как есть» is logged in `.hermes/grade-ledger.jsonl` without flipping `overall` to `PASS`).
2. For **`team_stop_active`**: use read-only council/diagnostics or emergency `manage_subagents(kill/kill_all)` to inspect/halt workers, then call `ask_question` («Разблокировать команду») for validated user unblock (`consent-validator.mjs`). Mechanical `PASS` never clears a hard-stop.
3. For **`l2_binding_uncertain`**: re-invoke the L2 auditor or grader as a single `invoke_subagent` call.
4. For **`plan_ask_mirror_invalid` / `logs_direct_write_deny`**: rewrite the plan confirmation question in plain Russian («Понял», «Добавлю сам», «Чего не делаю», «Вопросы») keeping IDs in `.hermes/plan.md`; export run logs strictly via `node scripts/export-logs.mjs` (see `skills/hermes/references/log-export-protocol.md`).
